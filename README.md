# Сервис управления фестивальными площадками

Консольное приложение для организаторов фестивалей: подбор и бронирование площадок,
проверка вместимости и доступности, ведение расписания мероприятий.

Репозиторий проекта: https://github.com/Mastertuz/festival-venue-service

## Назначение

Приложение помогает организаторам фестивалей подбирать и бронировать площадки: проверять
вместимость, доступность на нужную дату и формировать расписание мероприятий на площадке.
Сервис решает задачу быстрого сопоставления параметров фестиваля (ожидаемое количество
посетителей, дата проведения) с характеристиками доступных площадок.

## Целевая аудитория

- организаторы фестивалей и культурных мероприятий;
- администраторы площадок (парков, концертных залов, открытых пространств);
- координаторы, составляющие расписание фестивальных программ.

## Предметная область

Организация фестивалей требует учёта множества площадок с разной вместимостью,
расписанием занятости и набором организаторов, ответственных за проведение мероприятий.
Организатор может создавать фестивали и бронировать под них площадки на определённые даты.
Одна площадка не может иметь два активных бронирования на одну и ту же дату. Отменённое
бронирование не блокирует площадку и позволяет создать новое бронирование на эту дату.

## Основные сущности

### Venue — площадка

Объект `Venue` представляет площадку, доступную для проведения фестиваля.

Атрибуты: `id`, `name`, `capacity`.

Методы: `is_suitable_for(expected_attendees)` — проверка соответствия вместимости;
`__str__()` — строковое представление; `validate_capacity(capacity)` (`@staticmethod`) —
проверка корректности значения вместимости; `from_data(data)` (`@classmethod`) — создание
объекта из словаря.

### Organizer — организатор

Объект `Organizer` представляет ответственное лицо или организацию, проводящую фестиваль.

Атрибуты: `id`, `name`.

Методы: `__str__()` — строковое представление; `from_data(data)` (`@classmethod`) —
создание объекта из словаря.

### Festival — фестиваль

Объект `Festival` представляет мероприятие, для которого подбирается площадка.

Атрибуты: `id`, `name`, `date`, `expected_attendees`, `organizer` — объект `Organizer`.

Методы: `__str__()` — строковое представление с учётом организатора.

### Booking — расписание (бронирование)

Объект `Booking` связывает фестиваль с площадкой на определённую дату.

Атрибуты: `id`, `festival` — объект `Festival`, `venue` — объект `Venue`, `is_cancelled` —
признак отмены бронирования.

Методы: `cancel()` — отменить бронирование (не удаляя его из коллекции); `status`
(`@property`) — текстовый статус («активно» / «отменено»), доступен как атрибут без вызова;
`__str__()` — строковое представление с учётом статуса.

`Booking` не наследуется от `Festival` или `Venue` — отношения между сущностями
предметной области не образуют иерархию «является», поэтому вместо наследования
используется композиция: `Booking` хранит ссылки на связанные объекты.

## Взаимодействие объектов

```
Organizer ← Festival ← Booking → Venue
```

`Festival` хранит ссылку на связанного `Organizer` (`festival.organizer`). `Booking`
хранит ссылки на связанные `Festival` и `Venue` (`booking.festival`, `booking.venue`), что
даёт прямой доступ к их данным: `booking.venue.name`, `booking.festival.date`,
`booking.festival.organizer.name`.

## Возможности

- просмотр, поиск и сортировка площадок по вместимости, отбор по минимальной вместимости,
  проверка вместимости под ожидаемое число посетителей (`venue.is_suitable_for(...)`);
- учёт организаторов: добавление и поиск;
- учёт фестивалей: добавление (со связью с организатором), поиск по названию, сортировка
  по дате;
- бронирование площадки под фестиваль с проверкой вместимости и занятости даты, отмена
  бронирования без удаления из истории, просмотр расписания;
- сохранение и загрузка данных всех сущностей в JSON-файлах между запусками программы.

## Формат данных

JSON остаётся форматом хранения данных; при загрузке словари преобразуются в объекты
классов, при сохранении — обратно в словари. Связанные объекты хранятся в JSON по
идентификатору, а не целиком.

Площадки (`data/venues.json`): `{"id": 1, "name": "Городской парк", "capacity": 5000}`.

Организаторы (`data/organizers.json`): `{"id": 1, "name": "АНО «Арт-Ивент»"}`.

Фестивали (`data/festivals.json`): `{"id": 1, "name": "Фестиваль уличной музыки",
"date": "2026-06-12", "expected_attendees": 4500, "organizer_id": 1}` — при загрузке
`organizer_id` заменяется ссылкой на найденный объект `Organizer`.

Расписание (`data/bookings.json`) — связь фестиваля и площадки; дата берётся из фестиваля:
`{"id": 1, "festival_id": 1, "venue_id": 1, "is_cancelled": false}` — при загрузке
`festival_id`/`venue_id` заменяются ссылками на найденные объекты `Festival` и `Venue`.

## Требования

- Python 3.9+;
- pytest;
- flake8.

Установка зависимостей (рекомендуется в виртуальном окружении):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск программы

```bash
python main.py
```

## Запуск тестов

```bash
pytest
```

Тесты проверяют создание и работу объектов `Venue`, `Organizer`, `Festival` и `Booking`,
их методы, связь бронирования с фестивалем и площадкой, а также правило доступности
площадки (нельзя создать второе активное бронирование на ту же дату; отменённое
бронирование площадку не блокирует).
